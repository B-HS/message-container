# 인증 · MCP 합의 (2026-08-25)

## 결정

| 항목      | 결정                                                                                                                                                               |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 인증 방식 | better-auth 를 쓰지 않는다(초기 제안 철회). 자체 앱 패스워드 방식 채택                                                                                             |
| 초기 설정 | 컨테이너 기동 후 패스워드 미설정이면 웹 패널(`/panel`)에서 초기 패스워드 설정, 설정되어 있으면 로그인                                                              |
| API 키    | 패널 로그인 후 키 관리 페이지에서 계정(앱) 단위로 생성·폐기. prefix 는 `msg_`, 원문은 생성 시 1회만 표시하고 DB 에는 SHA-256 해시만 저장                           |
| API 보호  | `/api/*` 전체를 API 키(Bearer)로 보호. `/panel`·`/openapi.json` 은 공개                                                                                            |
| MCP       | 같은 서버의 `/mcp`(Streamable HTTP) 로 노출, API 키로 인증. 도구는 조회 4종 + run_sync + 첨부파일(base64 이미지/blob 포함) — 개인용이므로 비용·크기 제한 두지 않음 |
| OpenAPI   | `/openapi.json` 을 프로덕션 포함 항상 제공                                                                                                                         |
| 문서      | API 스펙 문서(docs/api.md)와 AI 용 MCP 가이드(docs/mcp.md) 작성                                                                                                    |

## 근거

- 개인용 단일 사용자 컨테이너라 계정 체계(가입·OAuth)가 불필요 — better-auth 도입 비용 대비 이득 없음
- 패스워드 해시는 Bun 내장 `Bun.password`(argon2id), 키 해시는 SHA-256 — 추가 의존성 없음
- 패널 세션은 인메모리(재시작 시 재로그인) — 단일 프로세스 개인용 전제
