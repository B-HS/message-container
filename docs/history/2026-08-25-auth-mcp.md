# 2026-08-25 — 인증 + MCP + 스펙 문서 이력

message-container 에 자체 앱 패스워드 인증·API 키·웹 패널·MCP 서버를 추가하고, 관련 스펙 문서를 작성한 작업 요약. 합의 근거는 [docs/acknowledge/2026-08-25-auth-mcp.md](../acknowledge/2026-08-25-auth-mcp.md), 진행 체크리스트는 [docs/PROCESS.md](../PROCESS.md) 참고.

## 1. 인증 · API 보호

- `service/domain/auth/auth-service.ts` — 패스워드 1회 설정, `Bun.password`(argon2id) 검증 + 5회 연속 실패 시 30초 잠금, 인메모리 패널 세션(TTL 12시간), API 키 발급(`msg_` prefix, 원문은 생성 시 1회만 반환하고 DB 엔 SHA-256 해시만 저장)·목록·폐기·검증
- `middleware/require-api-key.ts` — `/api/*` 전체에 `api.use('*', ...)` 로 적용, `Authorization: Bearer` 미검증 시 401 `UNAUTHORIZED` 봉투
- `lib/bearer-token.ts` — `Authorization: Bearer` 헤더 파싱
- `UNAUTHORIZED`(401) 에러 코드를 `lib/error-code.ts`·`lib/error-message.ts`·`lib/error.ts` 3파일에 추가

## 2. 웹 패널

- `route/panel.ts` — `GET /panel`(패스워드 미설정 시 초기 설정 폼 / 미로그인 시 로그인 폼 / 로그인 시 키 관리 화면), `POST /panel/setup·/login·/logout·/keys·/keys/:id/revoke`
- `dto/panel.ts` — `panelSetupSchema`(password 최소 8자 + confirm 일치 `refine`)·`panelLoginSchema`·`apiKeyCreateSchema`(name 1~100자)
- 신규 키는 응답 HTML 의 `<code data-new-key>` 안에 한 번만 노출되고, 이후 재조회할 수 없다

## 3. MCP 서버

- `route/mcp.ts` — `/mcp`(Streamable HTTP, `@hono/mcp` 의 `StreamableHTTPTransport`), 요청마다 새 `McpServer` + transport 를 생성하는 stateless 구조, API 키로 인증
- 도구 6종: `list_chats`·`get_chat_messages`·`search_messages`·`get_sync_status`·`run_sync`·`get_attachment`(이미지는 `image` 콘텐츠, 그 외는 base64 `resource` blob)
- API(`route/*.ts`)와 같은 Service 계층을 호출하므로 REST 응답과 MCP 도구 반환값이 동일하다

## 4. OpenAPI

- `/openapi.json` 을 프로덕션 포함 항상 노출하도록 변경(기존엔 문서화만 "비프로덕션" 이라고 적혀 있었고 실제 코드는 이미 무조건 노출이었다 — 이번에 문서를 코드에 맞춰 정정)
- `bearerAuth`(`type: http, scheme: bearer`) security scheme 을 전역 선언
